Layer 4: LUKS Duress Password

Registers a second passphrase on the LUKS header. Entering it at the boot prompt triggers the response below instead of unlocking normally. Your real passphrase is unaffected.

The decoy lives in a separate small LUKS volume unlocked by the duress passphrase. It has no reference to the real volume, so an observer cannot tell a decoy boot from a normal one.

🔴 THIS PERMANENTLY DESTROYS DATA. Erasing the LUKS keyslots makes every byte on the disk unrecoverable — there is no undo, and no recovery even with the correct passphrase. Keep verified offline backups, and test in a VM first. Typing the duress passphrase by mistake destroys the installation.

🌙 DuskyOS selected. Desktop and display server are set for you (Hyprland on Wayland) and those two questions are hidden. Watch the setup video and read the keybind cheatsheet before first boot.

🔒 Silent mode. A single secret is generated at install time and sealed on disk with permissions 600. At every boot the system recomputes the expected value and compares it internally. You are never shown a code and never type one.

  • Match — boot continues silently.
  • Mismatch — the boot chain was modified. You are warned before entering your passphrase.
⚠️ This only works with locked-down firmware. The check runs after your firmware does, so an attacker who can reflash firmware or boot other media can bypass it. It requires Secure Boot with your own keys (UKI + Custom Keys above), a firmware supervisor password, and USB/network boot disabled. How to lock down your firmware →

📱 Interactive mode. A QR code is shown once at install so you can add it to an authenticator, and you type a 6-digit code to log in. SHA-1 is used because every authenticator supports it; it is not a weakness in the way TOTP uses it.

⚠️ Recovery codes are printed once during setup. Store them off this machine. Losing your authenticator without them means you cannot log in.
